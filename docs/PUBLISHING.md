# 公开发布范围

## 可以公开的内容

公开仓库包含产品源码、构建与依赖配置、README、工程治理规则、经审阅的仓库评审技能、四份研究主题文档及通用部署说明。准确文件集合由根目录 public-files.json 指定；新增目录或文档必须显式纳入该白名单，再检查敏感信息。

研究文档陈述已验证能力、适用条件、必要扩展及验收要求。实验编号用于引用内部证据，不表示原始实验已经随公开源码交付，也不表示生产验收完成。

## 受控保存的内部材料

以下内容留在本地受控工作区，不进入公开 Git 文件集或 npm 包：

- validation 下的原始脚本、报告、日志、数据库、部署快照、研究冻结与迁移材料，以及哈希清单。
- 研究 archive 下的原始证据、历史汇编、历史入口与交接档案。
- 旧架构原件和旧实验实现说明。当前公开架构以研究主题文档为准。
- IDE 状态、运行时依赖、缓存、临时配置、环境文件及私钥。

原件和原哈希清单保持不变；不为公开发布原地脱敏。需要公开某份证据时，单独制作经审阅的脱敏副本，标明它与内部原件的关系，不将脱敏后的内容冒充原始清单覆盖的文件。备份与访问权限由内部存储负责，Git 忽略规则不提供加密或访问控制。

## 发布前检查

`pnpm check` 已包含公开范围检查；也可单独执行 `pnpm check:publication`，核对 Git 已跟踪及待加入的文件均在白名单内，且不含已知内网地址、个人目录、私钥或常见凭据模式。执行 `npm pack --dry-run --json` 可查看实际 npm 文件集合；package.json 的 files 是独立的打包白名单，当前 private=true，尚未授权发布 npm。

.gitignore 不会移除已被跟踪的文件；检查器会因此拒绝不在公开白名单内的已跟踪材料。原始证据、部署快照和 IDE 文件未被 Git 跟踪。2026-11-11 核对结论和适用范围后，清理了本地验证目录。研究历史档案仍保留在本地。本地现存材料仍会被直接压缩整个工作目录的操作带走；不要把工作目录整体打包作为公开发行物。Git 文件集和 npm 包应分别检查，新增打包/上传渠道也必须显式应用同一范围。

文档仅使用占位参数，不记录真实服务器地址、账号、部署/备份/证书路径、实例标识或当前授权状态。运行时应从受控配置读取实际参数。扫描器是静态检查，不能替代凭据管理或人工审阅。本次范围配置不执行 commit、push、上传或发布。
