## A3-07 Docker 启动与并发重投

2026-11-26，WORKER B 独占 Linux/amd64 Docker 租约，源码和 Go 控制程序均来自 `2d89b9a`。使用生产 `SingleHostExecution` 与 Go 权威 SQLite 账本，沙盒启动和停止观察通过受控适配器注入。控制器与目标容器均关闭外部网络，每个场景使用独立账本和目标。

| 场景                       | 结果                                                                                                                                                                                                                          |
| -------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 启动回执未返回时中断控制器 | 启动预约写入后，目标尚未运行时，同尝试重投保留原 Run 和 `START_UNKNOWN`。随后用真实 `docker start -a` 启动目标，原控制器仍在等待启动回执，此时定向 SIGKILL，退出码 137。重启后独立读取目标运行状态，原预约完成第 2 代 READY。 |
| 目标快速退出               | 目标写入一次后以 17 退出。重启重投保留第 1 代 `START_UNKNOWN` 和原 Run，新代未放行。                                                                                                                                          |
| 并发重投                   | 两个独立控制器共用原账本重投。一次发布第 2 代 READY，另一次被 CAS 拒绝，后续同尝试读回第 2 代 READY。                                                                                                                         |

每个场景独立核对 Docker 容器 ID 一致、目标计数文件只有一条记录，并以 SQLite 只读查询确认只有一条第 2 代启动预约。租约容器已全部清理。

复跑入口为 [A3-07 Docker 探针](../../../apps/orchestrator/acceptance/a3-07/run.sh)。在测试服务器创建新的私有目录并放入脚本、同目录的 `case.mjs`、Linux/amd64 Go 控制程序 `control` 及受测源码 `src/`。源码目录需包含可解析的 Orchestrator 运行依赖。进入该目录后执行 `bash run.sh`，使用服务器已有的 `node:24.19.0-bookworm-slim` 镜像。

### 真实 OpenShell 启动在途复验

同日，用 `10327aa` 加 MASTER 接管恢复候选源码复跑三个 Docker 探针，并使用生产 `commandHost`、官方 OpenShell 0.1.6 SDK 和真实 Gateway 复验启动在途。候选补丁只含 Orchestrator 生产源码，SHA-256 为 `81a58b1928a82b5b4d70518cc06f2b223f3bcdcf9460513288a3fa58957b3f6a`，验收时尚未合入。Go 控制源码与 `2d89b9a` 一致。

在 B 专属 Gateway 中新建沙盒和可挂载卷。控制器写入启动预约后，先重投一次并确认沙盒未运行、原 Run 保留且未放行。随后由独立受信 broker 发出真实 SDK `StartSandbox`，仅终止该租约的控制器。以派发时刻为基准，Docker 确认控制器已退出时为 122 毫秒，最后一条目标 Docker `start` 事件发生在 437 毫秒，SDK 确认 READY 在 1,879 毫秒。每个活动目标容器 ID 恰好对应一条 Docker 启动事件，挂载独占卷。重启后由命令宿主独立查询 Gateway，发布第 2 代 READY。容器集合保持一致，启动派发标记一次，账本只保留原启动预约。沙盒、卷及测试容器已清理。
