# A4 项目导入与共享卷验收证据

[返回 Readiness](../CURRENT-READINESS.md) · [部署与复跑入口](../../../deploy/README.md#共享卷宿主)

2026-11-26，测试服务器上同一轮使用两个同租户合法 Session、两个实际 OpenShell sandbox 和一个新建 Docker 命名卷。采用 Docker 28.1.1、OpenShell Gateway 0.1.6、真实 SDK protobuf 和 mTLS 上游。控制面通过 Execution HTTP 导入项目，以 Orchestrator 的可信 `sharedSessions` 绑定和签发执行授权。写入通过 SDK ingress 调用真实 sandbox，最终读写验证走普通 Run HTTP 和执行服务的 Worker 接入。Docker 读取容器挂载、卷身份和文件清单，SQLite 只读连接核对操作和回收回执。

| 场景                         | 结果 | 独立观测                                                                                                                                                                                                                                                                                                                                                                         |
| ---------------------------- | ---- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A4-01 导入、绑定、隔离与重建 | 通过 | 导入响应为 `importing`，随后为 `ready`。两条 Session 各有一个容器挂载到同一卷。其他 owner 查询项目返回 404，跨 owner 挂载被拒绝。删除并重建第二个 sandbox 后，容器 ID 改变，卷身份、路径、两份文件的 `0644` 权限及 SHA-256 均相同。                                                                                                                                              |
| A4-02 重复导入               | 通过 | 在原卷编辑 `README.md` 并新增 `draft.txt`。同键同输入返回 200 和原项目，同键异输入返回 `409 idempotency_conflict`。请求前后卷身份相同，路径、权限及三个文件的 SHA-256 均一致。                                                                                                                                                                                                   |
| A4-03 并发写入               | 通过 | S1 的真实 SDK 命令输出屏障后仍在运行，此时 S2 申请写授权收到 `volume_busy`，同一时刻从普通项目 Run HTTP 提交也返回 `409 volume_busy`。S2 的操作账本计数为 0，拒绝标记不存在。S1 完成并停止旧执行后，S2 重试成功，读到 S1 写入的内容并产生自己的标记。原未提交文件哈希保持一致。                                                                                                  |
| A1-05 单 Session 撤权        | 通过 | S1 先用合法 grant 读取文件，撤权后原 SDK 客户端和重连客户端均被拒绝，新授权申请也被拒绝，拒写标记不存在。S2 仍可在原卷读取并写入，工作区可独立读回。                                                                                                                                                                                                                             |
| A4-04 保留引用和最终回收     | 通过 | 两次提交 S1 释放请求都返回 `released`，同一卷仍存在。通过普通项目 Run HTTP 显式选择 S2 后真实读写成功，同键原 Session 重投为 200，变更 Session 为 409，未知 Session 为 404。释放 S2 后注入删卷失败，Docker 卷仍在、挂载数为 0、持久回执为待回收。重启同一控制器后自动完成删除，Docker 证实卷不存在，回执为已回收。重投返回 `reclaimed`，项目删除返回 204，随后读取项目返回 404。 |

## 来源 Session 修复复验

2026-11-26 在同一真实 Docker/OpenShell 候选环境复跑 A4-01～04 和 A1-05，五项通过。释放 S1 后，由仍为 READY 的 S2 绑定替代 Session，Docker 独立确认新 sandbox 挂载原卷。释放替代 Session 后，S2 的普通 Run 成功，随后释放最后一个引用并验证重启回收。候选源包 SHA-256 为 `5be92593565de3ba955ba8f7f4b9fc9fcb8ea3e28c754cfc71aa9f01507cf547`，结构化证据 SHA-256 为 `8e254d4dba574f16ba8d3d4a9165cd8a96e9572b6e7f16986bc9165144a9dee5`。

## 本地回归

Orchestrator 的 Execution Service 和 OpenShell 测试合计 190 项通过、2 项既有条件跳过。其中 180 项在聚合执行中通过，A1-03 的 SDK 生成前置在该轮失败，十项用例单独重跑均通过。新增共享卷回归核对撤权停止未确认时，控制器重启前后都保留写入门禁，以及回收重试沿用原回执。Orchestrator 类型检查、变更源文件 lint 和 npm 打包检查通过。服务启动接线在关闭共享卷功能时保留原有可信模块的七参数接口。

## Not Covered

本轮针对单执行宿主的项目共享卷。项目输入为普通 UTF-8 文件。绑定管理和执行授权使用可信控制面，未验证 Workspace Web 操作、Task 恢复、真实模型、PTY 或 SSH。回收故障使用宿主返回失败后关闭并重开控制器，未注入 Docker 删除请求在途故障。
