## 上传规格与验证基线

2026-11-13 核对主分支 `99246d5` 的代码与既有验证记录。该基线的空间 API 使用单文件 4 GB（4,000,000,000 字节）、每账号 10 GB（10,000,000,000 字节）和 16 MiB 分块。旧规格的 API 测试覆盖额度边界与并发预占。4 GB 浏览器实传及 10 GB 满额实传没有通过记录。

2026-11-13，在同一独立开发 Compose、Chromium 和私有 MinIO 上验证提交 `116dc7b7846225bc3d21c92d3e42c5b918c80554` 的个人端 API 与 Web，镜像 ID 为 `sha256:19d7dbb8d2fb8119f308b7a050859ee2e062caad1776bb26b26491e5d8ad474a`。验证入口见[空间上传实栈验收](../../deploy/README.md#空间上传实栈验收)。

- **WEB-A02**。先以 16,777,217 字节完成两块预检、页面保存、下载摘要和清理。实传 100,000,000 字节，断网刷新后回读第 1 块，同大小错文件返回 `409 space_conflict`。MinIO 对自然到期的第 2 块签名返回 403，重新授权后只 PUT 第 2 至 6 块且均返回 200。100,000,001 字节在页面及直接 API 拒收，API 返回 `413 file_limit`，无新增预占和对象。独立的 100 MB 下载复核通过，文件 SHA-256 为 `188cad9881a946c221b776a123284ea9fb15e5b34f6c402575cf945179045711`。证据来自多次运行，签名续传轮次在保存后因脚本状态回读断言失败而清理。
- **WEB-A03**。同账号通过浏览器实际保存两个 100,000,000 字节对象，已保存 200,000,000、预占 0。额外 1 字节返回 `409 space_quota`。删除一个对象后，两个各 100 MB 的并发开始请求仅一个预占成功。取消后核对对象与分块消失、额度释放并可再次预占。真实用例结束后项目和下载入口返回 404，存储无残留且用量复原。上传记录过期、已签发地址有效期内继续预占及存储清理失败由 API 受控时钟回归覆盖。
