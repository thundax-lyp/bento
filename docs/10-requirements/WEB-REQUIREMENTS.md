# Bento Web 产品需求

## 目的

Bento Web 是个人 Agent 工作台。受邀用户可以从空白工作区或自己的文件发起云端任务，离开后找回进度，在同一任务中继续迭代，查看结论与检查结果并下载文件变更补丁。云端任务的提交、找回、续做与审阅流程参考 [OpenAI Docs · Codex Cloud](https://learn.chatgpt.com/docs/cloud)。

## 范围

- 个人端的认证、私有项目和文件空间，以及从空白工作区或文件快照发起的任务。
- 沙盒执行、异步任务与连续对话、任务状态与历史、执行控制、结果审阅及交付。
- 多账号的资源隔离和公平派发。管理端及编排所有权见[应用与编排边界](APPLICATION-BOUNDARIES-REQUIREMENTS.md)。

## 非目标

- 公开注册、公开文件链接、计费、在线 IDE、终端直连。
- Git 仓库账号连接、仓库与分支选择、远端代码发布和 Pull Request 管理。
- 自动解压、通用二进制预览、在线覆盖正在使用的执行工作区。
- 用户自行重放未知副作用、手动调度 Worker、跨执行宿主自动接管。

## 页面与入口

| 入口       | 页面行为                                                                                                             |
| ---------- | -------------------------------------------------------------------------------------------------------------------- |
| 登录与账号 | 受邀用户经组织邀请邮件完成注册、邮箱验证和登录。登录后可恢复原任务或进入工作区。账号入口提供退出和重新认证后的注销。 |
| 新建任务   | 选择文件项目或空白工作区，确认输入基线，填写任务要求并提交。                                                         |
| 任务       | 按项目、状态筛选并搜索任务，查看摘要、更新时间和运行状态。                                                           |
| 任务详情   | 在同一页面查看消息、进度、结果和检查，提交后续要求，按状态取消或重试。                                               |
| 变更与交付 | 按文件审阅变更和检查结果，预览及下载补丁。                                                                           |
| 我的空间   | 查看存储用量和预占、上传与续传、浏览文件树、预览、下载和清理文件。                                                   |

## 功能需求

### WEB-01 账号和访问控制

邀请码和本地密码入口用于开发验证。

#### Purpose

让受邀用户安全进入 Bento 工作区，并在重复登录和服务重启后继续访问同一账号的资源。

#### Scope

- Bento 提供独立认证界面 `/auth`，工作区从 `/` 进入。`/auth` 及其子路径归认证入口处理。
- 身份服务负责发送邀请、注册、邮箱验证、设置密码、认证和身份审计。Bento 负责工作区准入、业务会话、资源归属和业务注销。
- 开发测试环境提供独立的远程身份服务和测试邮箱，开发者通过受控通道访问。

#### Non-goals

生产邮件投递、身份服务高可用、多身份绑定、身份服务管理员撤权后实时撤销 Bento 会话，以及旧部署账号迁移在本轮范围之外。

#### 业务规则

- 关闭公开注册。只有已验证邮箱并属于指定受邀组织的身份可以创建 Bento 业务会话。
- 首次成功认证后分配稳定的 `ownerId`。同一发行方下同一身份重复登录时复用该 ID。邮箱用于展示。业务资源的归属由 Bento 服务端校验。
- 退出结束当前 Bento 会话和对应的身份服务浏览器会话。注销需要用原身份重新认证，关闭 Bento 账号、撤销其业务会话并登记资源清理。身份服务账号由其管理员管理。
- 认证审计能查询注册、邮箱验证、凭据更新、登录和退出事件。

#### Acceptance Criteria

1. 未登录访问工作区进入 `/auth`。受邀用户完成邮件注册、邮箱验证和设置密码后登录，进入 `/`。认证子路径不会进入工作区路由。
2. 无邀请注册和已验证邮箱的非组织成员无法进入 Bento。首次合格登录产生一条持久绑定，并行重复登录及重启后重新登录复用原 `ownerId`。
3. 退出后旧会话失效。注销要求重新认证，关闭状态重启后保留。身份后台可查询该用户的认证事件。
4. 远程测试身份服务重启后，测试 Realm、客户端和历史审计可读。

- 项目、文件、上传会话、任务和补丁归所属账号。列表、详情、预览、下载、续传、完成、删除和签发传输地址均须校验归属。访问其他账号的资源时返回与资源不存在一致的结果。
- 上传和下载均通过 HTTPS。存储桶保持私有，浏览器只获得限时、限资源、限操作的传输权限。退出或会话过期后，须重新登录才能获取新权限。
- 登录失败、越权、任务错误与上传失败的页面和日志不得泄露邀请码、服务凭证、签名 URL、其他账号的数据或执行环境内部地址。

- 确认注销前展示数据清理时机和不可恢复的范围。注销立即撤销所有会话，已提交任务继续执行。任务全部结束后清理该账号的项目、工作区、上传文件、任务记录和 diff。待核对任务须先按 WEB-06 结案，未完成的分块上传须等待已签发地址到期。重启后继续未完成的清理。

#### WEB-01-HP01 Happy Path：受邀登录与持久身份

- 触发：受邀用户完成验证并登录。
- 行为与保护：从独立认证入口进入同一业务账号。
- 验收：验证 /auth 路由、各自项目可找回，并行登录和重启后复用同一 owner，身份审计可查（WEB-A01）。

#### WEB-01-HP02 Happy Path：退出与账号注销

- 触发：用户退出，或以原身份重新认证并确认注销。
- 行为与保护：退出结束对应会话。注销立即撤销全部业务会话，按任务和上传状态清理。
- 验收：核对影响提示、全会话失效、已提交任务继续，重启后恢复清理，历史认证审计仍可读。

#### WEB-01-BC01 Bad Case：身份不满足准入

- 触发：无邀请、邮箱未验证或非组织成员尝试登录。
- 行为与保护：拒绝创建业务会话，保护账号资源。
- 验收：逐种登录核对拒绝且未新增绑定，会话路由与提示不泄露凭据。

#### WEB-01-BC02 Bad Case：跨账号访问

- 触发：用另一账号访问项目、文件、上传会话、任务或补丁。
- 行为与保护：按资源不存在响应，保护归属与内容。
- 验收：逐类验证列表、预览、下载及续传、授权、完成、删除均无越权（WEB-A01）。

#### WEB-01-BC03 Bad Case：传输授权失效

- 触发：请求匿名、过期或错误资源及操作的传输授权。
- 行为与保护：私有对象不开放，会话失效后须重新登录获取新授权。
- 验收：对照有效 HTTPS 传输，逐类验证负请求被拒，页面和日志不泄密。

#### WEB-01-BC04 Bad Case：错误身份注销

- 触发：重新认证时使用不同身份。
- 行为与保护：拒绝注销并保护原账号与资源。
- 验收：核对账号未关闭、清理未登记。

#### WEB-01-BC05 Bad Case：注销清理尚有依赖

- 触发：注销时有待核对任务或签名仍有效的未完成上传。
- 行为与保护：先结案或等待签名到期，重启后继续清理。
- 验收：分别确认资源不会提前清理，条件满足后可清理，已关闭账号不能重新准入。

### WEB-02 上传与续传

- 用户可以选择或拖入文件，也可以选择文件夹并保留相对路径。上传前展示目标项目、文件清单、总大小、可用额度和拒收原因。拒绝无效路径、路径冲突和重复目标，禁止静默覆盖。上传进度按文件展示，批量失败时可针对未完成项继续。
- 单文件最大 **100 MB（100,000,000 字节）**。允许存储二进制文件。上传单个文件的限制与批量总量分开，批量仍受账号剩余额度约束。
- 大文件使用 S3 兼容的 Multipart Upload。浏览器按块并行直传私有对象存储。Bento 管理开始、分块授权、查询进度、完成和取消。每次授权限定上传会话、分块编号和该分块允许的字节数。文件正文不得经 Web 应用进程中转。分块大小、并行数和存储供应商由设计文档确定。
- 网络中断或分块签名过期后，可重新授权并只补传缺失或校验失败的分块。页面刷新或浏览器重开后，登录原账号并重新选择同一文件，可以恢复未过期的上传。继续前校验本地文件与已有分块匹配，拒绝将另一个文件拼入原上传。
- 上传记录应区分上传中、可继续、正在校验、已保存、已取消、已过期和失败。中间分块不出现在可下载文件树中。服务端核对实际大小、分块完整性和对象完整性后，才将文件标为已保存。重复完成请求返回同一文件。完成响应丢失时，应能查询原结果。

#### WEB-02-HP01 Happy Path：选择并保存多分块文件

- 触发：选择文件或文件夹，文件大小合规。
- 行为与保护：展示目标、清单、额度和进度，保留相对路径，经私有存储直传并核验。
- 验收：验证小型多分块上传、清理与下载摘要；恰好 100,000,000 字节可保存，浏览器正文不经过应用（WEB-A02）。

#### WEB-02-BC01 Bad Case：路径冲突

- 触发：包含无效路径、重复目标或路径冲突。
- 行为与保护：展示拒收原因，原文件不被覆盖。
- 验收：每类输入独立拒绝，原文件字节不变（WEB-A05）。

#### WEB-02-BC02 Bad Case：单文件超限

- 触发：提供 100,000,001 字节文件。
- 行为与保护：在传输前拒绝并提示单文件上限。
- 验收：核对无分块传输，与账号额度错误区分（WEB-A02）。

#### WEB-02-BC03 Bad Case：网络断开

- 触发：上传途中断网，刷新或重开浏览器后以原账号重选原文件。
- 行为与保护：恢复有效会话，只补缺失或校验失败的分块。
- 验收：核对补传分块编号和最终原始摘要（WEB-A02）。

#### WEB-02-BC04 Bad Case：分块签名过期

- 触发：分块签名失效，上传记录仍有效。
- 行为与保护：只为所需会话、分块和字节数重新授权。
- 验收：旧签名拒绝，新签名完成原文件且摘要一致（WEB-A02）。

#### WEB-02-BC05 Bad Case：重选内容不同

- 触发：选择同大小但内容不同的文件续传。
- 行为与保护：拒绝拼入原上传，保护已确认分块。
- 验收：无新分块混入，原文件仍能恢复（WEB-A02）。

#### WEB-02-BC06 Bad Case：完成回执丢失

- 触发：存储已完成，客户端未收到回执。
- 行为与保护：查询或重试返回原文件，记录及额度只记一次。
- 验收：重放后只见一条已保存记录和一次占用（WEB-A04）。

#### WEB-02-BC07 Bad Case：分块或对象不完整

- 触发：缺分块、大小不符或完整性核验失败。
- 行为与保护：保持相应的未完成、失败或清理状态，不得开放下载。
- 验收：分别读回对象、文件树和上传记录，半成品不可用（WEB-A04）。

### WEB-03 空间额度与文件生命周期

- 每账号 **200 MB（200,000,000 字节）**，覆盖用户保存在「我的空间」的文件及上传预占。开始上传时以服务端原子校验并预占声明大小。完成前核验实际大小，超出预占或单文件上限的上传不得登记为可用文件。完成后预占转为已保存用量，不重复记账。
- 取消或过期后应终止上传，清理未完成分块和未登记对象，再释放预占。清理中须能查询状态。服务重启、请求重试和并发完成或取消后，文件记录、对象与额度必须能够对账。过期时间在上传记录中可见。
- 区分单文件超限、账号空间不足、项目无法用于任务和任务队列已满。提示显示对应原因和可以采取的动作。
- 用户可以下载原始文件并删除自己保存的文件或项目。删除前明确列出影响，项目删除须说明其文件、任务历史与补丁是否一并移除。项目整体删除包括这些资源，并在确认前保留下载入口。
- 有未完成上传时，先取消并清理再删除项目。有排队、执行中、恢复中或待核对的任务时，拒绝删除项目及其使用的输入。任务结束后删除单个空间文件，历史任务及补丁仍可查看。删除完成后移除对应下载入口、回收已清理文件的额度，重复删除不重复扣减。

#### WEB-03-HP01 Happy Path：保存、下载和额度记账

- 触发：上传有效对象并完成核验。
- 行为与保护：预占转为已保存用量，原文件可下载。
- 验收：保存两个恰好 100 MB 的文件达到 200 MB，核对字节、额度和下载摘要（WEB-A03）。

#### WEB-03-HP02 Happy Path：删除文件或项目

- 触发：用户确认影响，且不存在阻断条件。
- 行为与保护：删除文件保留历史结果；删除项目移除其关联入口，清理后回收额度。
- 验收：确认前仍可下载，分别验证删除后入口、历史保留或移除、用量及重复删除（WEB-A05）。

#### WEB-03-BC01 Bad Case：并发预占超额

- 触发：配额耗尽或多个上传并发预占。
- 行为与保护：原子拒绝超额，对应提示区分单文件、项目和排队限制。
- 验收：满额再试 1 字节，独立测并发，已保存与预占之和不越界（WEB-A03）。

#### WEB-03-BC02 Bad Case：上传取消或过期

- 触发：用户取消或上传超过有效期。
- 行为与保护：先终止传输、清理分块及未登记对象，再释放预占。
- 验收：分别核对清理中状态、对象消失后额度可复用，以及可见到期时间（WEB-A03）。

#### WEB-03-BC03 Bad Case：完成与取消竞争

- 触发：同一会话并发完成和取消或期间服务重启。
- 行为与保护：持久文件、对象和额度保持同一结果。
- 验收：覆盖竞争与重启重放，核对无半成品、无重复扣减或释放（WEB-A04）。

#### WEB-03-BC04 Bad Case：删除项目有未完成上传

- 触发：删除请求到达时项目仍有未完成上传。
- 行为与保护：先取消并清理上传。
- 验收：先确认上传清理，再检查项目删除和额度释放顺序。

#### WEB-03-BC05 Bad Case：删除命中未结束任务

- 触发：项目或输入被排队、执行、恢复或待核对任务引用。
- 行为与保护：拒绝删除，保留任务输入及下载入口。
- 验收：逐状态验证删除受阻，任务结案后允许删除（WEB-A05）。

### WEB-04 项目与 Agent 输入

- 「我的空间」中的已保存文件、执行工作区中的文件和 Run 产出的 diff 在页面上明确区分。用户上传的原文件保持可取回，Agent 的变更通过任务详情交付。
- 文件快照入口使用文本项目导入契约，最多 100 个 UTF-8 文件、合计 1 MiB 文本。首次运行前，用户从项目已保存文件中选择符合条件的输入以初始化执行工作区。超出执行范围的文件仍可保存和下载，提交任务前须提示哪些文件无法用于本次执行。不得静默跳过用户选中的文件。
- 任务提交时明确显示项目和使用的输入。排队、执行和恢复期间，上传或删除其他空间文件不得改变该任务的输入及执行工作区。原有项目和任务历史按原账号可继续访问。

#### WEB-04-HP01 Happy Path：选择项目文本快照

- 触发：从已保存项目选择符合导入规格的文本。
- 行为与保护：页面显示实际选择及项目，固定初始输入，原文件独立于工作区和 diff。
- 验收：核对正常提交、源文件下载、任务结果和历史各自可读（WEB-A07）。

#### WEB-04-BC01 Bad Case：所选文件不能执行

- 触发：选择无效路径、非 UTF-8 或超出文件数或 1 MiB 限制的输入。
- 行为与保护：提示具体不合格文件或整组限制，拒绝整组无效选择，仍保留源文件下载。
- 验收：分别验证 100 文件与 1 MiB 边界，混合无效选择不创建任务，原文件仍可下载。

#### WEB-04-BC02 Bad Case：任务建立后项目变动

- 触发：排队、执行或恢复时增删未绑定空间文件或轮换环境。
- 行为与保护：保护提交时快照与绑定工作区。
- 验收：比对 Run 输入、冻结摘要与版本，改动不进入旧任务（WEB-A07）。

### WEB-05 执行环境

- 首次登录后可直接以空白工作区发起任务，无需先建项目或上传文件。用户也可以用已保存文件的快照初始化工作区。任务使用平台分配的沙盒及其预置工具、进程环境和权限。用户在任务中使用项目自己的依赖清单和命令准备依赖。
- 提交时固定任务的输入基线和平台运行环境版本。页面显示准备状态和脱敏后的失败原因。尚未受理的提交可修正后再提交。已受理的任务可在原地址按原输入和环境版本重新准备。若需变更输入基线或环境版本，须由用户确认后另建任务，原任务及其失败记录保留。
- 每个任务拥有独立执行工作区。同一任务的后续 Run 复用它的会话和工作区。不同任务即使使用相同文件项目或平台环境，也各自持有工作区，互相看不到未交付的改动。密钥按执行阶段和授权范围使用，浏览器和执行记录均不得返回密钥值。

#### WEB-05-HP01 Happy Path：首次使用默认执行环境

- 触发：新受邀账号用空白工作区或有效快照发起任务。
- 行为与保护：按提交时基线和环境版本进入分配的沙盒。
- 验收：验证两种入口、预置工具、项目依赖命令、正常领取与结果（WEB-A06、WEB-A07）。

#### WEB-05-HP02 Happy Path：保留历史的续做和另建

- 触发：完成后续做或确认使用新输入、环境另建。
- 行为与保护：续做沿用原会话和卷，另建独立工作区并保留旧记录。
- 验收：核对绑定、历史与结果，两个同项目任务互不读取未交付改动（WEB-A06、WEB-A07）。

#### WEB-05-BC01 Bad Case：准备失败

- 触发：任务尚未受理或已受理后准备失败。
- 行为与保护：显示脱敏原因；尚未受理可修正，已受理按原地址与冻结版本重新准备。
- 验收：分开复现两种状态；修复后原址继续，变更基线或版本需用户确认另建（WEB-A06）。

#### WEB-05-BC02 Bad Case：提交响应丢失

- 触发：提交已受理但响应未到达用户。
- 行为与保护：复用原记录，保护冻结版本和执行次数。
- 验收：重试没有第二次派发（WEB-A06）。

#### WEB-05-BC03 Bad Case：超范围使用环境凭据

- 触发：浏览器或工具尝试访问不属于当次阶段和授权的秘密。
- 行为与保护：隔离密钥，页面、日志和产物不暴露密钥值。
- 验收：实际沙盒运行受限工具，检查凭据扫描正对照与实际零命中（WEB-A07）。

### WEB-06 任务提交与结果

- 提交成功后进入可重新打开的任务详情。同一提交因超时或断网重试时，返回原 Run 或原提交结果，防止重复排队。同一任务已有活跃 Run 时提示用户等待或取消。账号达到排队上限时明确拒绝当前提交，其他账号仍可提交。
- 页面显示准备中、排队中、执行中、恢复中、待核对、取消中、已取消、已完成或失败。断开连接或关闭页面后，已接受的任务继续在服务端推进。刷新、重连或重新登录后，可按原账号找回同一任务及其最新状态。
- Worker 接管时保留原 Run、Session 和 Workspace，拒绝旧执行代继续写入。未知工具结果不得自动重放。待核对时展示「上一次操作结果未确认」，保留任务入口并暂不提供 diff。可信侧核对完成且任务成功后，可在原任务下载补丁。
- 进入待核对时通知可信运维方，并在任务详情显示等待处理的原因及下一步。可信运维方负责接手和记录结论。确认成功且结果完整时交付原 Run 的结果。确认失败时保留失败原因，仅在确认可安全重试时开放重试。证据不足且继续调查无法确认时，可信运维方可在确认旧执行停止、撤权且相关资源可安全清理后，以「结果无法确认」结案。该任务关闭执行和交付入口，用户可查看脱敏结论，并可在确认适合独立开展工作时新建任务。项目删除和注销清理可继续，结案审计按部署规则保留。
- diff 预览与下载来自同一份结果。失败时显示可公开的原因。成功且无变更时可以下载空 diff，页面明确区分「无变更」和「结果尚不可用」。

#### WEB-06-HP01 Happy Path：任务提交、关页与结果交付

- 触发：受邀账号提交有效任务。
- 行为与保护：记录可重开的地址，服务端在关页后继续，原账号可回读原 Run。
- 验收：三个账号使用同一真实模型与 OpenShell 环境，从上传到关页、找回、预览和可应用补丁独立对账（WEB-A08）。

#### WEB-06-HP02 Happy Path：查询终态和无变更结果

- 触发：Run 成功交付、无变更或明确失败。
- 行为与保护：展示同一结果的预览与下载，区分空 diff、尚不可用和脱敏失败原因。
- 验收：分别核对成功、有空 diff、失败的入口与结果状态。

#### WEB-06-BC01 Bad Case：提交响应丢失

- 触发：提交已受理，但超时或断线导致客户端未收到响应。
- 行为与保护：重投同一提交时返回原结果，保留原 Run。
- 验收：按原请求重投，核对返回的是原 Run 且只排队一次。

#### WEB-06-BC07 Bad Case：同任务已有活跃 Run

- 触发：同一任务已有活跃 Run，用户再次发送要求。
- 行为与保护：提示等待或取消，保护活跃 Run。
- 验收：提交新的要求，核对没有创建另一个活跃 Run。

#### WEB-06-BC02 Bad Case：租户队列满

- 触发：一个账号达到排队上限。
- 行为与保护：明确拒绝该账号，保留其他账号可提交，区分空间额度和队列。
- 验收：A 拒绝、B/C 仍可提交，上传阶段不占执行槽（WEB-A09）。

#### WEB-06-BC03 Bad Case：执行落盘后回执前中断

- 触发：并发执行时强杀已写入但未回执的 Worker。
- 行为与保护：保留原 Run、Session、Workspace，拒绝旧代写入，未知结果不重放。
- 验收：A 待核对且无下载，B 原 Worker 完成可下载，C 按队列处理，独立核对副作用次数（WEB-A10）。

#### WEB-06-BC04 Bad Case：待核对后确认成功

- 触发：可信侧能确认原 Run 成功且结果完整。
- 行为与保护：记录结论，在原页面交付原 Run 结果。
- 验收：核对待核对时无下载、成功确认后可获取对应补丁（WEB-A10）。

#### WEB-06-BC05 Bad Case：待核对后确认失败

- 触发：可信侧确认原操作失败。
- 行为与保护：保留失败原因，只在安全时开放重试。
- 验收：在原页面核对原因和入口，条件不足时拒绝重试（WEB-A10）。

#### WEB-06-BC06 Bad Case：证据不足时可信结案

- 触发：调查后仍无法确认结果，旧执行已确认停止、撤权且资源可清理。
- 行为与保护：通知与记录可信运维结论，关闭原任务执行和交付，保留脱敏审计。
- 验收：确认不可再执行或下载，用户可查结论，可独立新建，项目删除及注销清理可继续（WEB-A10）。

### WEB-07 连续对话与任务控制

连续任务 MVP 对应 WEB-07-HP01～HP03，用户安全重试 WEB-07-HP04 可独立交付。MVP 必须保留账号授权、任务间工作区隔离、此前的 Run 和结果，并保持提交幂等。停止和撤权未确认时保留槽位，副作用不明时禁止重放与续写，安全条件不足时关闭重试。安全重试开放前须通过适用的 Bad Case。

#### WEB-07-HP01 Happy Path：重连恢复历史与进度（MVP）

- 触发：两个浏览器打开同一任务，其中一个临时断开。
- 行为与保护：保留已确认内容并提示重连，恢复历史后再更新进度。
- 验收：分别对照用户消息、Agent 回复、步骤、命令和检查，反复拉取保持时间顺序且无重复（WEB-A11）。

#### WEB-07-HP02 Happy Path：原任务继续对话（MVP）

- 触发：已有成功轮次且任务状态允许续做。
- 行为与保护：原 Task、Session 和工作区继续，生成独立 Run，旧结果与检查保留。
- 验收：正常页面追加依赖此前改动的要求，重放同一发送请求，核对只新增一个 Run，旧差异和检查仍可读（WEB-A11）。

#### WEB-07-HP03 Happy Path：同项目另建独立任务（MVP）

- 触发：同一项目另建任务。
- 行为与保护：新任务使用独立工作区和会话，保护未交付改动。
- 验收：回读两任务的工作区绑定，新任务看不到旧任务的未交付标记（WEB-A11）。

#### WEB-07-HP04 Happy Path：用户安全重试

- 触发：成功轮次之后，后续 Run 部分写入后明确失败或确认取消，且安全条件和两个原始检查点均有效。
- 行为与保护：提示丢弃本轮未完成改动，在原任务重试同一轮要求，新 Run 独立且原尝试仍可查。
- 验收：从真实页面重试，在新执行前分别读回工作区与 Session 检查点；此前成功改动和旧结果保留，部分文件及会话改动退出新执行基线，重放同键仍返回同一新 Run（WEB-A12）。

#### WEB-07-BC01 Bad Case：取消排队任务

- 触发：用户取消仍在队列中的 Run。
- 行为与保护：记录已取消，保留任务和 Run 历史。
- 验收：在派发前取消后释放执行容量，核对目标仍已取消且无派发（WEB-A12）。

#### WEB-07-BC02 Bad Case：运行中取消仍占槽

- 触发：请求取消执行中的 Run，停止或撤权未确认。
- 行为与保护：显示取消中并占槽，撤权后旧执行拒写，停止与撤权均确认后才释放。
- 验收：控制停止确认，核对另一 Run 仍排队；确认两条件后才显示已取消、旧代写入拒绝、后续 Run 入槽（WEB-A12）。

#### WEB-07-BC03 Bad Case：副作用未知

- 触发：执行停止或失败后无法确认操作副作用。
- 行为与保护：显示待核对及原因，保留记录，阻止自动重放、用户重试和后续写入，按 WEB-06 结案。
- 验收：制造一项未知操作，分别尝试重试与续写，核对两者均拒绝且无新执行或重放（WEB-A12）。

#### WEB-07-BC04 Bad Case：工作区检查点不可用

- 触发：原 Run 明确失败或取消，Session 检查点有效，工作区检查点缺失或损坏。
- 行为与保护：说明不能安全恢复并关闭重试，保留当前卷、Session 和原 Run。
- 验收：只破坏工作区检查点，正常入口重试被拒，无新 attempt，无卷或 Session 变更（WEB-A12）。

#### WEB-07-BC05 Bad Case：Session 检查点不可用

- 触发：原 Run 明确失败或取消，工作区检查点有效，Session 检查点缺失或损坏。
- 行为与保护：说明不能安全恢复并关闭重试，保留当前卷、Session 和原 Run。
- 验收：只破坏 Session 检查点，正常入口重试被拒，无新 attempt，无卷或 Session 变更（WEB-A12）。

#### WEB-07-BC06 Bad Case：受理重试后检查点失效

- 触发：重试请求已受理，但任一检查点在实际恢复前失效。
- 行为与保护：阻断恢复和后续执行，避免错误基线或部分覆盖。
- 验收：在受理与恢复之间使检查点失效，核对无新执行、卷不变，重复同键可回读原受理回执（WEB-A12）。

### WEB-08 结果审阅与交付

- 结果页按 Run 显示摘要、变更文件、逐文件 diff 和检查结果。检查应区分通过、失败、未运行和无法运行，并提供可公开的输出。只读调查或无文件变更的任务仍可交付结论。已交付结果与其基线绑定，后续 Run 不覆盖旧结果。
- 每个可交付的 Run 结果同时提供本轮增量和相对任务初始输入的累计变更。空白任务以空工作区为基线，文件任务以冻结的输入快照为基线。累计变更用于审阅和下载补丁，预览与下载绑定同一结果版本。

#### WEB-08-HP01 Happy Path：按 Run 审阅和下载

- 触发：同一任务完成两轮相互依赖的修改。
- 行为与保护：每轮独立显示摘要、文件、逐文件 diff、检查和累计补丁。
- 验收：各轮补丁应用到原始快照得到对应结果，预览和下载版本一致（WEB-A13）。

#### WEB-08-HP02 Happy Path：只读或无文件变化

- 触发：Run 成功且无文件改动。
- 行为与保护：可交付结论，空 diff 与结果不可用可区分。
- 验收：读取结论、检查和空 diff，结果仍绑定对应 Run（WEB-A13）。

#### WEB-08-BC01 Bad Case：后轮完成后读取旧结果

- 触发：用户在新 Run 完成后重开旧结果或下载旧补丁。
- 行为与保护：保护旧结果与原基线，不受后轮覆盖。
- 验收：核对旧结果预览与下载摘要和首次一致（WEB-A13）。

#### WEB-08-BC02 Bad Case：检查失败或无法执行

- 触发：检查失败、未运行或无法运行。
- 行为与保护：分别显示实际状态和允许公开的输出。
- 验收：逐状态核对结果，失败或无法执行不显示为通过，输出不暴露私有内容。

## 业务规则

- 每账号拥有一个私有空间，可包含多个项目。额度按账号计算，项目用于组织文件与任务。
- 文件大小与空间用量按实际字节计。预占中的文件不对任务或下载开放。账号额度与租户的任务排队上限独立。
- 上传入口用于创建项目和保存输入。用户用新的文件快照重新开始时，应显式选择新任务的输入基线。已有任务仍可从原地址取回结果。
- 单宿主双槽部署优先派给当前无任务在跑的租户，租户内按提交顺序。单租户可以用满两槽，恢复计入在跑数。槽位和队列容量由部署配置决定。

## 验收标准

下表保留既有端到端验收组编号。执行时可复用账号、项目与 Run，每个场景按上文稳定场景编号独立记录结果。分批交付时，按该批声明的场景及其安全和数据约束验收。

| 编号    | 验收场景与通过条件                                                                                                                                                                                                                                                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WEB-A01 | 三个受邀账号分别从浏览器上传自己的项目。刷新或重新登录后，文件树和任务历史可找回。尝试读取其他账号的文件、获取传输授权、续传、完成、删除或下载补丁，均与资源不存在一致。                                                                                                                                                              |
| WEB-A02 | 先在同一真实环境从页面选择小型多分块文件，验证保存、下载内容和清理。再上传恰好 100,000,000 字节的文件，中途断网、刷新并重选原文件后只补传缺失分块。分块签名过期且上传记录有效时可重新授权。重选同大小但内容不同的文件时拒绝续传。下载后校验与源文件一致。100,000,001 字节在传输前拒绝。                                               |
| WEB-A03 | 同账号实际保存两个各 100,000,000 字节的文件，恰好占满 200,000,000 字节后拒绝新增 1 字节。多个上传并发开始时，已保存与预占总量不得超过上限。取消、上传记录过期或删除后，仅在确认存储已清理时释放额度，并验证释放后的额度可重用。                                                                                                       |
| WEB-A04 | 模拟完成请求的回执丢失并重试，文件只出现一次，额度只记一次。测试缺失分块、大小不符、服务重启和完成与取消并发，确认无半成品可下载且额度最终一致。                                                                                                                                                                                      |
| WEB-A05 | 上传带子目录的项目，核对树结构、文件大小、预览和下载。路径穿越和重名冲突被拒绝。删除前显示影响，存在未结束任务时拒绝删除。任务结束后删除项目，确认关联入口失效且用量减少。                                                                                                                                                            |
| WEB-A06 | 新受邀账号从空状态用默认环境发起空白任务，关闭页面后找回任务并取得结果。另模拟准备失败，排除故障后按原输入和环境版本从原地址继续，提交回执丢失时仅执行一次。变更输入基线或环境版本时，经确认另建任务，原失败记录仍可查。                                                                                                              |
| WEB-A07 | 用文件快照提交任务，排队后修改项目文件并发布新平台环境版本。原任务仍使用提交时的快照和环境版本。验证命令和文件操作发生在所分配的沙盒中，两个任务的未交付改动互相隔离，页面、日志及产物均不出现平台密钥值。                                                                                                                            |
| WEB-A08 | 在同一远端环境使用真实模型与 OpenShell。三个账号各自通过 Web 上传符合要求的项目、提交任务、在 Run 仍活跃时关闭页面，从原账号找回同一 Run，确认任务在页面关闭期间继续推进，并预览、下载可应用到原始文件的补丁。大文件可保存和下载，选作不支持的任务输入时得到明确提示。                                                                |
| WEB-A09 | A 的任务队列满时，A 获得明确拒绝，B、C 仍能提交。上传大文件期间不占用执行槽，上传额度不足的提示与任务队列满可区分。                                                                                                                                                                                                                   |
| WEB-A10 | A、B 并发，C 排队。A 写入落盘后、回执前强杀其 Worker。B 在原 Worker 上完成并下载 diff，A 保留原 Run、Session 和 Workspace，旧执行代被拒，UNKNOWN 不重放。验证待核对时不可下载，确认成功后原页面可取回结果，确认失败时显示原因。模拟证据不足并由可信运维方结案，确认任务不再执行或交付，项目删除和账号注销清理可以继续，结案审计可查。 |
| WEB-A11 | 从两个浏览器打开同一任务，断开再连接，历史、进度和检查无重复。完成后追加要求，确认使用原 Session 与工作区、产生独立 Run，并可查看上一轮结果。同一项目另起任务，确认未交付改动互不影响。                                                                                                                                               |
| WEB-A12 | 按 [WEB-07](#web-07-连续对话与任务控制) 分别核验用户安全重试、排队取消、运行取消占槽、UNKNOWN、工作区检查点缺失、Session 检查点缺失，以及重试受理后检查点失效。                                                                                                                                                                       |
| WEB-A13 | 从文件快照发起任务，关闭页面后找回，在同一任务完成两轮相互依赖的修改。分别查看每轮增量、累计变更和检查结果。下载所选 Run 的累计补丁，应用到原始快照后得到该轮结果。第二轮完成后，第一轮预览和下载仍对应原结果。只读任务可查看结论。                                                                                                   |
