# Bento Web 产品需求

## 目的

受邀用户可以在浏览器准备代码和执行环境、把工作交给云端 Agent、离开后恢复查看进度、审阅结果并继续迭代，最终通过补丁或 Pull Request 交付。产品参照 Codex Web 的云端编码流程。参照能力见 [OpenAI Docs · Codex Cloud](https://learn.chatgpt.com/docs/cloud)和[云端环境](https://learn.chatgpt.com/docs/environments/cloud-environments)。

## 范围

- 个人端的认证、私有项目和文件空间，以及从空白工作区、文件快照或授权 Git 仓库发起的任务。
- 可复用的执行环境、异步任务与连续对话、任务状态与历史、执行控制、结果审阅及交付。
- 多账号的资源隔离和公平派发。管理端及编排所有权见[应用与编排边界](APPLICATION-BOUNDARIES-REQUIREMENTS.md)。

## 非目标

- 公开注册、公开文件链接、计费、在线 IDE、终端直连和自动合并 PR。
- 自动解压、通用二进制预览、在线覆盖正在使用的执行工作区。
- 用户自行重放未知副作用、手动调度 Worker、跨执行宿主自动接管。

## 功能需求

### WEB-01 账号和访问控制

邀请码和本地密码入口用于开发验证。

#### Purpose

让受邀用户安全进入 Bento 工作区，并在重复登录和服务重启后继续访问同一账号的资源。

#### Scope

- Bento 提供独立认证界面 `/auth`，工作区从 `/` 进入。`/auth` 及其子路径归认证入口处理。
- 身份服务负责发送邀请、注册、邮箱验证、设置密码、认证和身份审计。Bento 负责工作区准入、业务会话、资源归属和业务注销。
- 开发测试环境提供独立的远程身份服务和测试邮箱，开发者通过受控通道访问。

#### Non-goals

生产邮件投递、身份服务高可用、多身份绑定、身份服务管理员撤权后实时撤销 Bento 会话，以及旧部署账号迁移在本轮范围之外。

#### 业务规则

- 关闭公开注册。只有已验证邮箱并属于指定受邀组织的身份可以创建 Bento 业务会话。
- 首次成功认证后分配稳定的 `ownerId`。同一发行方下同一身份重复登录时复用该 ID。邮箱用于展示。业务资源的归属由 Bento 服务端校验。
- 退出结束当前 Bento 会话和对应的身份服务浏览器会话。注销需要用原身份重新认证，关闭 Bento 账号、撤销其业务会话并登记资源清理。身份服务账号由其管理员管理。
- 认证审计能查询注册、邮箱验证、凭据更新、登录和退出事件。

#### Acceptance Criteria

1. 未登录访问工作区进入 `/auth`。受邀用户完成邮件注册、邮箱验证和设置密码后登录，进入 `/`。认证子路径不会进入工作区路由。
2. 无邀请注册和已验证邮箱的非组织成员无法进入 Bento。首次合格登录产生一条持久绑定，并行重复登录及重启后重新登录复用原 `ownerId`。
3. 退出后旧会话失效。注销要求重新认证，关闭状态重启后保留。身份后台可查询该用户的认证事件。
4. 远程测试身份服务重启后，测试 Realm、客户端和历史审计可读。

- 项目、文件、上传会话、任务和补丁归所属账号。列表、详情、预览、下载、续传、完成、删除和签发传输地址均须校验归属。访问其他账号的资源时返回与资源不存在一致的结果。
- 上传和下载均通过 HTTPS。存储桶保持私有，浏览器只获得限时、限资源、限操作的传输权限。退出或会话过期后，须重新登录才能获取新权限。
- 登录失败、越权、任务错误与上传失败的页面和日志不得泄露邀请码、服务凭证、签名 URL、其他账号的数据或执行环境内部地址。

- 确认注销前展示数据清理时机和不可恢复的范围。注销立即撤销所有会话，已提交任务继续执行。任务全部结束后清理该账号的项目、工作区、上传文件、任务记录和 diff。待核对任务须先按 WEB-06 结案，未完成的分块上传须等待已签发地址到期。重启后继续未完成的清理。

### WEB-02 上传与续传

- 用户可以选择或拖入文件，也可以选择文件夹并保留相对路径。上传前展示目标项目、文件清单、总大小、可用额度和拒收原因。拒绝无效路径、路径冲突和重复目标，禁止静默覆盖。上传进度按文件展示，批量失败时可针对未完成项继续。
- 单文件最大 **4 GB（4,000,000,000 字节）**。允许存储二进制文件。上传单个文件的限制与批量总量分开，批量仍受账号剩余额度约束。
- 大文件使用 S3 兼容的 Multipart Upload。浏览器按块并行直传私有对象存储。Bento 管理开始、分块授权、查询进度、完成和取消。每次授权限定上传会话、分块编号和该分块允许的字节数。文件正文不得经 Web 应用进程中转。分块大小、并行数和存储供应商由设计文档确定。
- 网络中断或分块签名过期后，可重新授权并只补传缺失或校验失败的分块。页面刷新或浏览器重开后，登录原账号并重新选择同一文件，可以恢复未过期的上传。继续前校验本地文件与已有分块匹配，拒绝将另一个文件拼入原上传。
- 上传记录应区分上传中、可继续、正在校验、已保存、已取消、已过期和失败。中间分块不出现在可下载文件树中。服务端核对实际大小、分块完整性和对象完整性后，才将文件标为已保存。重复完成请求返回同一文件。完成响应丢失时，应能查询原结果。

### WEB-03 空间额度与文件生命周期

- 每账号 **10 GB（10,000,000,000 字节）**，覆盖用户保存在「我的空间」的文件及上传预占。开始上传时以服务端原子校验并预占声明大小。完成前核验实际大小，超出预占或单文件上限的上传不得登记为可用文件。完成后预占转为已保存用量，不重复记账。
- 取消或过期后应终止上传，清理未完成分块和未登记对象，再释放预占。清理中须能查询状态。服务重启、请求重试和并发完成或取消后，文件记录、对象与额度必须能够对账。过期时间在上传记录中可见。
- 区分单文件超限、账号空间不足、项目无法用于任务和任务队列已满。提示显示对应原因和可以采取的动作。
- 用户可以下载原始文件并删除自己保存的文件或项目。删除前明确列出影响，项目删除须说明其文件、任务历史与补丁是否一并移除。项目整体删除包括这些资源，并在确认前保留下载入口。
- 有未完成上传时，先取消并清理再删除项目。有排队、执行中、恢复中或待核对的任务时，拒绝删除项目及其使用的输入。任务结束后删除单个空间文件，历史任务及补丁仍可查看。删除完成后移除对应下载入口、回收已清理文件的额度，重复删除不重复扣减。

### WEB-04 项目与 Agent 输入

- 「我的空间」中的已保存文件、执行工作区中的文件和 Run 产出的 diff 在页面上明确区分。用户上传的原文件保持可取回，Agent 的变更通过任务详情交付。
- 文件快照入口使用文本项目导入契约，最多 100 个 UTF-8 文件、合计 1 MiB 文本。首次运行前，用户从项目已保存文件中选择符合条件的输入以初始化执行工作区。超出执行范围的文件仍可保存和下载，提交任务前须提示哪些文件无法用于本次执行。不得静默跳过用户选中的文件。
- 任务提交时明确显示项目和使用的输入。排队、执行和恢复期间，上传或删除其他空间文件不得改变该任务的输入及执行工作区。原有项目和任务历史按原账号可继续访问。

### WEB-05 仓库与执行环境

- 用户可以连接、查看和解除 GitHub 授权。仅列出当前账号获准访问的仓库和分支。任务提交时记录已解析的 commit，分支随后移动时，排队任务仍使用原基线。授权撤回后拒绝新的检出和写入，已保存的 Bento 任务历史仍受账号归属保护。
- 首次登录后可直接以默认环境和空白工作区发起任务，无需先建项目、上传文件或连接 GitHub。每次新建任务可选默认环境或已配置环境。可复用环境支持设置运行时、依赖安装或初始化命令、环境变量、密钥引用和网络权限，保存前可以验证配置。任务固定提交时选定的环境版本，并显示准备状态和脱敏后的失败原因。
- 授权、输入或环境准备失败时，页面保留任务要求和选择并给出可操作的原因。尚未受理的提交可修正后再提交。已受理的任务可从原地址修复并再次准备。若修复改变输入基线或环境版本，须由用户确认后另建任务，并保留原任务及其失败记录。
- 每个任务拥有独立执行工作区。同一任务的后续 Run 复用它的会话和工作区。不同任务即使使用相同仓库、文件项目或环境，也各自持有工作区，互相看不到未交付的改动。密钥按执行阶段和授权范围使用，浏览器和执行记录均不得返回密钥值。

### WEB-06 任务提交与结果

- 提交成功后进入可重新打开的任务详情。同一提交因超时或断网重试时，返回原 Run 或原提交结果，防止重复排队。同一任务已有活跃 Run 时提示用户等待或取消。账号达到排队上限时明确拒绝当前提交，其他账号仍可提交。
- 页面显示准备中、排队中、执行中、恢复中、待核对、取消中、已取消、已完成或失败。断开连接或关闭页面后，已接受的任务继续在服务端推进。刷新、重连或重新登录后，可按原账号找回同一任务及其最新状态。
- Worker 接管时保留原 Run、Session 和 Workspace，拒绝旧执行代继续写入。未知工具结果不得自动重放。待核对时展示「上一次操作结果未确认」，保留任务入口并暂不提供 diff。可信侧核对完成且任务成功后，可在原任务下载补丁。
- 进入待核对时通知可信运维方，并在任务详情显示等待处理的原因及下一步。可信运维方负责接手和记录结论。确认成功且结果完整时交付原 Run 的结果。确认失败时保留失败原因，仅在确认可安全重试时开放重试。证据不足且继续调查无法确认时，可信运维方可在确认旧执行停止、撤权且相关资源可安全清理后，以「结果无法确认」结案。该任务关闭执行和交付入口，用户可查看脱敏结论，并可在确认适合独立开展工作时新建任务。项目删除和注销清理可继续，结案审计按部署规则保留。
- diff 预览与下载来自同一份结果。失败时显示可公开的原因。成功且无变更时可以下载空 diff，页面明确区分「无变更」和「结果尚不可用」。

### WEB-07 连续对话与任务控制

- 同一任务按时间展示用户消息、Agent 回复、面向用户的执行步骤、命令和检查摘要。重新打开时先恢复历史，再更新进度。临时断线保留最后确认的内容并提示重新连接，重复拉取不得生成重复消息。
- 已结束且状态可继续的任务支持发送后续要求。后续要求追加到同一任务和 Session，生成独立 Run 和结果记录，保留之前的差异与检查。发送请求重试只产生一次 Run。
- 用户可取消排队任务或请求停止运行中的任务。运行中的任务先显示取消中，确认撤权和停止后才显示已取消并释放槽位。若副作用未知，显示待核对并保留记录。待核对状态阻止重试及后续写入，处理结果按 WEB-06 结案。
- 明确失败或确认取消后，只有确认重试安全且可恢复到原 Run 执行前的工作区和会话检查点时，才允许重试。重试沿用该轮要求，创建新 Run，保留原尝试及此前成功轮次的改动。页面提示本轮未完成的工作区改动将被丢弃。无法满足条件时说明原因并关闭重试入口。

### WEB-08 结果审阅与代码交付

- 结果页按 Run 显示摘要、变更文件、逐文件 diff 和检查结果。检查应区分通过、失败、未运行和无法运行，并提供可公开的输出。只读调查或无文件变更的任务仍可交付结论。已交付结果与其基线绑定，后续 Run 不覆盖旧结果。
- 每个可交付的 Run 结果同时提供本轮增量和相对任务初始输入的累计变更。空白任务以空工作区为基线，文件任务以冻结的输入快照为基线，仓库任务以提交时冻结的 commit 为基线。累计变更用于审阅和下载补丁，预览与下载绑定同一结果版本。
- 仓库任务支持在用户明确确认后创建 PR。确认界面展示仓库、目标分支、基线、完整交付变更和检查状态。实际发布内容须与确认内容一致。发布时重新校验写权限、目标基线及结果版本。授权失效时可重新授权后回到原结果确认。目标基线或交付内容变化时须重新准备并审阅，原结果仍可查看和下载。
- 创建 PR 的响应丢失时应查询原结果或安全重试。成功后在原任务的对应结果中记录 PR 链接。后续 Run 不自动更新已发布的 PR。运行 Agent、查看 diff 和继续对话均不会触发发布。

## 业务规则

- 每账号拥有一个私有空间，可包含多个项目。额度按账号计算，项目用于组织文件与任务。
- 文件大小与空间用量按实际字节计。预占中的文件不对任务或下载开放。账号额度与租户的任务排队上限独立。
- 上传入口用于创建项目和保存输入。用户用新的文件快照重新开始时，应显式选择新任务的输入基线。已有任务仍可从原地址取回结果。
- 单宿主双槽部署优先派给当前无任务在跑的租户，租户内按提交顺序。单租户可以用满两槽，恢复计入在跑数。槽位和队列容量由部署配置决定。

## 验收标准

| 编号    | 验收场景与通过条件                                                                                                                                                                                                                                                                                                                    |
| ------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| WEB-A01 | 三个受邀账号分别从浏览器上传自己的项目。刷新或重新登录后，文件树和任务历史可找回。尝试读取其他账号的文件、获取传输授权、续传、完成、删除或下载补丁，均与资源不存在一致。                                                                                                                                                              |
| WEB-A02 | 上传恰好 4,000,000,000 字节的文件。中途断网、刷新并重新选择原文件后，只补传缺失分块。签名过期可重新授权。重新选择不同文件时拒绝续传。下载后校验与本地原文件一致。多 1 字节的文件在开始传输前拒绝。                                                                                                                                    |
| WEB-A03 | 同账号上传 4 GB、4 GB、2 GB 文件，恰好占满 10 GB 后拒绝新增 1 字节。多个上传并发开始时，保存与预占总量不得超过上限。取消、过期及删除后，确认存储已清理且额度可重新使用。                                                                                                                                                              |
| WEB-A04 | 模拟完成请求的回执丢失并重试，文件只出现一次，额度只记一次。测试缺失分块、大小不符、服务重启和完成与取消并发，确认无半成品可下载且额度最终一致。                                                                                                                                                                                      |
| WEB-A05 | 上传带子目录的项目，核对树结构、文件大小、预览和下载。路径穿越和重名冲突被拒绝。删除前显示影响，存在未结束任务时拒绝删除。任务结束后删除项目，确认关联入口失效且用量减少。                                                                                                                                                            |
| WEB-A06 | 新受邀账号从空状态用默认环境发起空白任务，关闭页面后找回任务并取得结果。另模拟准备失败，修复原配置后从原地址继续，提交回执丢失时仅执行一次。变更输入基线或环境版本时，经确认另建任务，原失败记录仍可查。                                                                                                                              |
| WEB-A07 | 连接 GitHub，选择授权仓库和分支并复用已验证环境。提交后更新分支和环境配置，确认原任务仍使用提交时的 commit 和环境版本。撤权后拒绝新检出及写入，密钥不会出现在页面、日志或产物中。                                                                                                                                                     |
| WEB-A08 | 在同一远端环境使用真实模型与 OpenShell。三个账号各自通过 Web 上传符合要求的项目、提交任务、在 Run 仍活跃时关闭页面，从原账号找回同一 Run，确认任务在页面关闭期间继续推进，并预览、下载可应用到原始文件的补丁。大文件可保存和下载，选作不支持的任务输入时得到明确提示。                                                                |
| WEB-A09 | A 的任务队列满时，A 获得明确拒绝，B、C 仍能提交。上传大文件期间不占用执行槽，上传额度不足的提示与任务队列满可区分。                                                                                                                                                                                                                   |
| WEB-A10 | A、B 并发，C 排队。A 写入落盘后、回执前强杀其 Worker。B 在原 Worker 上完成并下载 diff，A 保留原 Run、Session 和 Workspace，旧执行代被拒，UNKNOWN 不重放。验证待核对时不可下载，确认成功后原页面可取回结果，确认失败时显示原因。模拟证据不足并由可信运维方结案，确认任务不再执行或交付，项目删除和账号注销清理可以继续，结案审计可查。 |
| WEB-A11 | 从两个浏览器打开同一任务，断开再连接，历史、进度和检查无重复。完成后追加要求，确认使用原 Session 与工作区、产生独立 Run，并可查看上一轮结果。同一项目另起任务，确认未交付改动互不影响。                                                                                                                                               |
| WEB-A12 | 分别取消排队和运行中的任务。运行中须确认停止才释放槽位。模拟副作用未知，待核对期间拒绝重试和继续写入。在此前成功轮次的基础上，让后续 Run 写入部分文件后取消或失败。安全重试从该轮执行前检查点开始，保留此前成功改动和原记录。缺少检查点或副作用无法确认时，页面说明原因并禁用重试。                                                   |
| WEB-A13 | 在真实仓库发起任务，关闭页面后找回，连续完成两轮修改且第二轮依赖第一轮。审阅累计 diff 和检查，确认后创建 PR。核对 PR 完整变更与确认内容一致，原任务记录唯一 PR 链接。验证无写权限、重新授权、分支冲突、结果变化和创建回执丢失。文件任务的两轮累计补丁应可应用到原始快照，并得到所选结果。                                             |
