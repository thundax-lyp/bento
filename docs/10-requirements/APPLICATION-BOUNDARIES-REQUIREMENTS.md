# 应用与编排边界需求

## Purpose And Scope

个人端和管理端分别提供认证入口、业务页面和 API。两端通过内部接口使用统一的任务编排能力。任务 Worker 独立运行，并按当次授权执行。

## Non-goals

首版以单执行宿主为范围。跨节点自动接管、多实例调度与滚动升级在后续范围内。恢复范围是已持久化的会话检查点、文件与业务执行状态。进程内存和浏览器现场快照不在恢复范围内。

## 业务规则

- 各端分别处理业务会话与用户授权。任务编排服务验证调用方身份、允许的操作和目标资源范围。
- 同一 Run 只有一个权威写入方。重投复用当前持久执行尝试。确认旧执行停止后释放槽位，结果未知的副作用等待核对。
- Worker 使用当次执行授权。撤销后，旧代请求无法继续执行或写入会话历史。

## Acceptance Criteria

1. 个人端和管理端的认证入口、页面和 API 各自独立，两个 API 都通过内部接口访问同一编排服务。
2. 单宿主正常派发、超时撤权和进程重启恢复均可验证。启动请求在途时重投不会重复启动同一次尝试。
3. 旧代拒写、持久状态读回和 `UNKNOWN` 对账在真实执行链中通过验证。

## 执行链验收门槛

部署配置应明确执行节点范围和开放的执行入口。未启用的 PTY、SSH 等入口须拒绝调用。

| 编号              | 实现验收门槛                                                                 | 必须提供的可核验结果                                                                                                                                          |
| ----------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| A1 身份与绑定     | 登录身份到 Workspace/Session/Run/沙盒/Volume 的服务端映射；动态凭据签发/撤销 | 伪造 tenant/Session/卷、旧 capability、直接 SDK/Gateway/管理入口均拒绝；worker 读不到数据库和管理凭据；不撤销共享卷上其他合法 Session                         |
| A2 持久会话       | 完整 provider/checkpoint、持久批次 ID/回执、恢复与审计                       | 旧代 append/flush/close 拒绝；重启/ACK 丢失/事务中途崩溃/调用方崩溃后历史及回执一致；新 worker 自主发现待对账批次                                             |
| A3 接管状态机     | 将服务端入口、撤权、stop/observe/start、CAS、READY 放入同一恢复协议          | 每个阶段强杀控制器及丢回包；旧连接/重连/在跑子进程不能继续写；新代不提前放行；迟到 stop 不杀新实例；UNKNOWN 不盲重放。100ms 入口轮询/断流本身不算进程停止证明 |
| A4 数据生命周期   | 真实项目导入、同卷共享/隔离、删除重建及回收                                  | staging/READY、文件清单/权限/哈希、重复导入、未提交文件保护；并发写按明确冲突策略处理；删除 Session 不误删共享卷                                              |
| A5 最终执行链     | 在选定生产版本/transport 上复跑同一纵向业务链                                | 文件/Bash/PTC/子 Agent，以及启用时的 PTY；真实模型任务、工具后崩溃、worker 接管、沙盒重建后历史与 Workspace 正确，UNKNOWN 无盲重放；不能拼接不同轮次代替      |
| A6 调度与池化     | Temporal Run 编排，worker 领取/失联/取消/审批及重用                          | Activity 重试不重复副作用；长期复用无凭据/监听器/连接/缓存串 Session；升级可排空；配额、公平性、背压与资源上限有拒绝证据                                      |
| A7 部署等级       | 声明单节点或多节点服务承诺                                                   | 单节点也有备份及还原演练；承诺多节点时须验存储/数据库故障、失联宿主、分区、多控制器竞争，记录明确 RPO/RTO。SQLite 单机与 Docker 本地卷不自动升级为 HA         |
| A8 证据与可运维性 | 固定依赖、部署/回滚、审计与告警、测试清理                                    | source revision/镜像摘要、操作账本、机器断言、独立状态观测、失败记录、无秘密的结果和新哈希清单；版本变化重验受影响路径                                        |

Go Orchestrator 接管执行链时，A3、A5 和 A6 的验收应覆盖正常派发、超时清理、快速退出后重投、`docker start` 请求在途时强杀、同一尝试并发重投、旧代拒写、宿主与沙盒双侧停止观察和 `UNKNOWN` 恢复。真实 OpenShell 验收须能独立核对副作用次数。
