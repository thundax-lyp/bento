# 应用与编排边界需求

## Purpose And Scope

个人端和管理端分别提供认证入口、业务页面和 API。两端通过内部接口使用统一的任务编排能力。任务 Worker 独立运行，并按当次授权执行。

## Non-goals

首版 MVP 采用单执行宿主。可选的双执行宿主部署按 [A7](#a7-部署等级) 验收人工故障转移。跨节点自动接管、多实例调度与滚动升级在后续范围内。恢复范围是已持久化的会话检查点、文件与业务执行状态。进程内存和浏览器现场快照不在恢复范围内。

## 业务规则

- 各端分别处理业务会话与用户授权。任务编排服务验证调用方身份、允许的操作和目标资源范围。
- 同一 Run 只有一个权威写入方。重投复用当前持久执行尝试。确认旧执行停止后释放槽位，结果未知的副作用等待核对。
- Worker 使用当次执行授权。撤销后，旧代请求无法继续执行或写入会话历史。

## Acceptance Criteria

1. 个人端和管理端的认证入口、页面和 API 各自独立，两个 API 都通过内部接口访问同一编排服务。
2. 单宿主正常派发、超时撤权和进程重启恢复均可验证。启动请求在途时重投不会重复启动同一次尝试。
3. 旧代拒写、持久状态读回和 `UNKNOWN` 对账在真实执行链中通过验证。

## 执行链验收门槛

同一次部署验收可覆盖多项门槛。以各项实际观测结果为准。部署配置应明确执行节点范围和开放的执行入口。未启用的 PTY、SSH 等入口须拒绝调用。

### Docker/OpenShell 故障注入

- 仅中断场景指定的组件或执行尝试。Worker 故障按 Run、执行代和沙盒实例定位，在指定边界触发受控异常退出。控制器故障使用独占候选实例，在指定持久阶段中断。启动请求在途场景须保留请求及容器状态供恢复侧观察，容器仍由 Docker 管理。
- 禁止使用宿主 PID 信号、`docker kill` 或停止、重启共享容器来模拟局部故障。需要重建独占容器时，使用 Docker/OpenShell 生命周期接口，并独立回读目标实例状态。A7 部署级故障演练使用独占候选环境，按演练范围操作。
- 独立核对中断发生的边界、目标退出、回执及副作用，验证同一部署内未被注入故障的执行继续推进。无法隔离目标或证明注入时机时，记录验收受阻。
- A2 等本地进程级测试可向测试直接创建并持有的独占子进程注入退出，用于核验事务原子性和重投语义。

## 分项验收场景

首版 MVP 为独立应用入口和单执行宿主的正常执行、授权、数据持久化与可复验部署。每次交付声明启用范围及通过的场景编号，并满足单权威写入、旧代拒写、受信停止后释放槽位、未知副作用不重放。单节点证据不能覆盖多节点或高可用承诺，后续部署按声明验证对应场景。

### APP-01 独立应用入口

#### APP-01-01 [Happy Path] 双端独立入口与共享编排

- 触发：分别进入个人端和管理端并提交授权业务操作。
- 行为与保护：两端各自提供认证、页面与 API，内部接口使用同一编排，Worker 独立执行。
- 验收：检查两端入口边界及服务端调用，独立回读各端操作对应的权威 Run。

#### APP-01-02 [Bad Case] 跨端或越权调用

- 触发：以错误调用方身份、操作或资源范围访问编排。
- 行为与保护：拒绝调用，保护另一端账号、资源和权威状态。
- 验收：分别注入三种错误，确认无 Run 或授权变更。

### A1 身份与绑定

#### A1-01 [Happy Path] 服务端绑定与当次授权

- 触发：已认证账号发起允许的任务。
- 行为与保护：服务端确定 Workspace、Session、Run、沙盒及 Volume，并签发限于当次执行的凭据。
- 验收：独立核对各层绑定及签发和撤销记录。

#### A1-02 [Bad Case] 伪造资源绑定

- 触发：调用伪造 tenant、Session 或卷。
- 行为与保护：拒绝访问，保持真实资源绑定。
- 验收：各伪造值分别被拒且无跨租户数据。

#### A1-03 [Bad Case] 旧执行授权

- 触发：执行授权已撤销，旧代仍发送请求。
- 行为与保护：拒绝旧 capability。
- 验收：回读撤销状态，旧代不能执行或追加历史。

#### A1-04 [Bad Case] 绕过受信入口

- 触发：Worker 直接访问 SDK、Gateway、管理入口或数据库凭据。
- 行为与保护：拒绝未授权直连，隐藏管理和数据库凭据。
- 验收：逐入口核对拒绝，检查 Worker 环境、日志和挂载无凭据。

#### A1-05 [Bad Case] 共享卷上的单 Session 撤权

- 触发：多个合法 Session 使用同卷，其中一个撤权。
- 行为与保护：只撤对应 Session 权限。
- 验收：被撤会话拒写，其余合法会话保持访问。

### A2 持久会话

#### A2-01 [Happy Path] 持久批次与恢复

- 触发：Worker 追加并完成一批会话历史。
- 行为与保护：provider 和 checkpoint 持久化历史、批次 ID、回执和审计；恢复后可重新读回。
- 验收：读取历史及回执，重启后核对一致并让合法代继续追加。

#### A2-02 [Bad Case] 旧代操作

- 触发：旧代尝试 append、flush 或 close。
- 行为与保护：拒绝修改 Session 和批次。
- 验收：独立尝试三种操作，历史及回执不变。

#### A2-03 [Bad Case] 提交确认丢失

- 触发：批次提交后 ACK 未收到并重投。
- 行为与保护：复用持久批次和原回执。
- 验收：检查历史只追加一次，相同请求读到原回执。

#### A2-04 [Bad Case] 事务中途崩溃

- 触发：在会话持久事务提交前、后分别使目标持久化进程异常退出。
- 行为与保护：恢复后保持历史与回执一致。
- 验收：分别重启核对事务边界，无半批次。

#### A2-05 [Bad Case] 调用方崩溃

- 触发：调用方退出，现场存在未对账批次。
- 行为与保护：新 Worker 自主发现并继续对账。
- 验收：重启后无需旧调用方介入即可发现该批，历史及回执一致。

### A3 接管状态机

单执行宿主要通过完整接管验收，必须支持按执行代定位原实例、恢复后继启动预约，并阻止原代通过直挂卷继续写入。

#### A3-01 [Happy Path] 单权威执行及接管

- 触发：正常派发或受信侧开始接管。
- 行为与保护：统一协调撤权、停止观察、新代启动、CAS 和 READY，一次只放行一个写入方。
- 验收：核对正常派发及接管的身份、阶段与宿主/沙盒停止证明。

#### A3-02 [Bad Case] 控制阶段崩溃

- 触发：在各恢复阶段中断独占候选控制器。
- 行为与保护：从持久状态恢复，保留相同 Run 和尝试，不提前放行。
- 验收：各阶段单独注入，核对停止证据、CAS 和唯一 READY。

#### A3-03 [Bad Case] 阶段响应丢失

- 触发：停止、观察或启动回包丢失。
- 行为与保护：按原持久尝试对账，无第二执行。
- 验收：分别丢回包并重放请求，核对真实副作用次数。

#### A3-04 [Bad Case] 撤权后仍有旧连接

- 触发：旧连接、重连或运行中的子进程继续写入。
- 行为与保护：撤权前确认原代对挂载卷停写，撤权时关闭既有执行连接并拒绝旧授权重连。槽位保留至受信侧分别确认 Worker 和沙盒停止。
- 验收：分别核对既有连接、旧授权重连、旧子进程持久化和直接写卷。独立观察原沙盒和 Worker，并核对两侧停止确认之间槽位仍被占用。

#### A3-05 [Bad Case] 迟到的停止请求

- 触发：新实例已开始，旧 stop 迟到。
- 行为与保护：请求只作用于原执行代。
- 验收：实际新实例不受旧 stop 影响。

#### A3-06 [Bad Case] 副作用未知

- 触发：无法确定旧执行操作结果。
- 行为与保护：进入 UNKNOWN 等待核对，保护持久进度。
- 验收：重放请求不重新执行未知操作。

#### A3-07 [Bad Case] 启动在途与并发重投

- 触发：docker start 请求在途或快速退出，随后重投同一尝试。
- 行为与保护：继续对账原尝试，不重复启动。
- 验收：分别验证启动请求在途时控制器中断、目标执行快速退出和并发重投，独立核对容器状态及副作用次数。

### A4 数据生命周期

#### A4-01 [Happy Path] 导入及卷生命周期

- 触发：真实项目导入，随后按契约共享、隔离、删除或重建。
- 行为与保护：按 staging 到 READY 管理，保留准确文件、权限和哈希，按引用回收。
- 验收：核对导入树、同卷绑定、隔离、删除与重建。

#### A4-02 [Bad Case] 重复导入

- 触发：同一导入请求重投。
- 行为与保护：按契约对账，保护现存文件和未提交改动。
- 验收：比对清单、哈希与卷，重复导入不破坏工作区。

#### A4-03 [Bad Case] 共享卷并发写入

- 触发：多个合法会话同时写同卷。
- 行为与保护：执行约定冲突策略，保护无关未提交文件。
- 验收：制造真实竞争并核对拒绝或冲突结果及文件哈希。

#### A4-04 [Bad Case] 共享卷仍有引用

- 触发：删除使用共享卷的一个 Session。
- 行为与保护：保留其他合法 Session 使用的卷。
- 验收：核对仍有引用时可读写，最终合法引用释放后可回收。

### A5 最终执行链

#### A5-01 [Happy Path] 单轮真实纵向链路

- 触发：使用选定生产版本、transport 和真实模型执行任务。
- 行为与保护：从正常入口实际执行文件、Bash、PTC、子 Agent 和已启用的 PTY。
- 验收：同一轮回读 Run、Session、Workspace 及工具结果。

#### A5-02 [Bad Case] 未启用执行入口

- 触发：调用当前部署未启用的 PTY、SSH 等入口。
- 行为与保护：拒绝操作，保护沙盒和任务。
- 验收：独立验证禁用入口没有启动执行。

#### A5-03 [Bad Case] 工具完成后崩溃

- 触发：工具产生副作用后、回执持久化前，目标 Worker 执行异常退出。
- 行为与保护：安全接管或重建沙盒，保护历史、Workspace 和未知结果。
- 验收：在同一真实链路验证重建、旧代拒写和 UNKNOWN 不重放，独立核对副作用次数。

### A6 调度与池化

#### A6-01 [Happy Path] Run 派发、审批与受控复用

- 触发：Temporal 调度可执行 Run。
- 行为与保护：按配额、公平性、背压及资源上限领取，支持审批、取消及 Worker 重用。
- 部署启用 Task Run 审批时，待审批 Run 占用队列额度并保留 Task 的单活跃 Run 约束。批准后才可派发，拒绝、取消或账号关闭可终止待审批 Run。
- 验收：记录实际调度、Run 归属、审批和资源回收。分别核对批准只派发一次，拒绝、取消和账号关闭均不产生执行。

#### A6-02 [Bad Case] Activity 重试

- 触发：Activity 响应丢失或同一尝试重投。
- 行为与保护：复用当前持久执行尝试。
- 验收：独立核对实际副作用次数和原回执。

#### A6-03 [Bad Case] 失联或超时

- 触发：Worker 失联或到达执行期限。
- 行为与保护：撤权并观察退出，避免提前释放或调度旧代。
- 验收：核对心跳、停止、槽位和后续派发。

#### A6-04 [Bad Case] 容量耗尽

- 触发：触及配额、背压或资源上限。
- 行为与保护：按公平性约束拒绝或等待而不越限。
- 验收：分别观察拒绝原因、获准任务及实际资源占用。

#### A6-05 [Bad Case] 跨会话池重用

- 触发：旧 Session 的 Worker 被新 Session 使用。
- 行为与保护：隔离凭据、监听器、连接和缓存。
- 验收：长时间重用及独立检查无串 Session。

#### A6-06 [Bad Case] 升级遇到活跃执行

- 触发：已支持的升级在仍有在途 Run 时开始。
- 行为与保护：可排空原执行后切换。
- 验收：核对未提前释放、排空和切换结果。

### A7 部署等级

双宿主首版按人工故障转移验收。备用端从已独立校验的一致检查点恢复。接管前须通过独立管理面确认原端停写，控制权交接只允许一个宿主继续写入。记录检查点后丢失的已确认数据，以及从故障触发到备用端完成后续执行的时长。自动故障转移、物理断电和检查点后仍在途的副作用另行验收。

#### A7-01 [Happy Path] 声明部署范围并备份还原

- 触发：验收声明范围内的单节点部署。
- 行为与保护：保留持久会话、文件和业务执行状态，记录还原证据。
- 验收：执行单节点备份还原，回读状态和继续执行，记录实际 RPO/RTO（适用时）。

#### A7-02 [Bad Case] 单节点进程重启

- 触发：执行进程停止后重启。
- 行为与保护：按持久状态恢复，保护历史和已写文件。
- 验收：对账重启前后 Run、回执、Session 和工作区。

#### A7-03 [Bad Case] 多节点存储或数据库故障

- 触发：已承诺多节点的部署失去存储或数据库。
- 行为与保护：按该部署恢复契约处理，维持权威写入。
- 验收：分别演练故障并记录一致性、RPO/RTO。

#### A7-04 [Bad Case] 多节点失联与分区

- 触发：已承诺多节点的部署失去宿主或发生网络分区。
- 行为与保护：保护写入权和执行状态。
- 验收：分别模拟两种故障，读回接管次数和 RPO/RTO。

#### A7-05 [Bad Case] 多控制器竞争

- 触发：已承诺多节点的部署有两个控制器竞争。
- 行为与保护：保护同一 Run 的唯一权威写入。
- 验收：并发触发恢复，独立核对实际执行和数据一致性。

### A8 证据与可运维性

#### A8-01 [Happy Path] 部署、审计与清理

- 触发：按固定依赖部署并执行验收。
- 行为与保护：记录源码 revision、镜像摘要、操作账本、机器断言、独立观察及无秘密的结果；清理测试资源。
- 验收：一份可追溯证据清单能回读实际身份、审计与逐项清理。

#### A8-02 [Bad Case] 部署失败或回滚

- 触发：部署异常或触发恢复到前版本。
- 行为与保护：保留失败记录，按声明范围回滚并核对状态。
- 验收：实际运行回滚与告警，读回镜像、数据库及卷一致性。

#### A8-03 [Bad Case] 受测版本发生变化

- 触发：源码、依赖或镜像变更影响已验路径。
- 行为与保护：记录新的内容哈希并重验受影响场景。
- 验收：旧证据与新版本边界明确，回读新的结果和摘要。
