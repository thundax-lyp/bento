# 应用与编排边界需求

## Purpose And Scope

个人端和管理端分别提供认证入口、业务页面和 API。两端通过内部接口使用统一的任务编排能力。任务 Worker 独立运行，并按当次授权执行。

## Non-goals

首版以单执行宿主为范围。跨节点自动接管、多实例调度与滚动升级在后续范围内。

## 业务规则

- 各端分别处理业务会话与用户授权。任务编排服务验证调用方身份、允许的操作和目标资源范围。
- 同一 Run 只有一个权威写入方。重投复用当前持久执行尝试。确认旧执行停止后释放槽位，结果未知的副作用等待核对。
- Worker 使用当次执行授权。撤销后，旧代请求无法继续执行或写入会话历史。

## Acceptance Criteria

1. 个人端和管理端的认证入口、页面和 API 各自独立，两个 API 都通过内部接口访问同一编排服务。
2. 单宿主正常派发、超时撤权和进程重启恢复均可验证。启动请求在途时重投不会重复启动同一次尝试。
3. 旧代拒写、持久状态读回和 `UNKNOWN` 对账在真实执行链中通过验证。
