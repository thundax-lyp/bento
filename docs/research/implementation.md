# 实施顺序与验收条件

研究可行性阶段已结束；以下未完成项进入实现验收，不自动启动新调查。

## 实施顺序

| 阶段                 | 交付内容                                                            | 复用基础与必要实现                                                                                   | 放行条件                                                              |
| -------------------- | ------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------- |
| 1 可信绑定和服务入口 | 用户/项目/Session/Run/沙盒/卷映射、动态身份、受控 SDK/SSH 入口      | 现成身份服务、OpenShell 原生认证、已有 ingress/broker；补业务 ACL、capability 生命周期与管理凭据隔离 | A1；未支持入口明确关闭；partial 的部署信任边界明确                    |
| 2 持久会话和接管     | provider 服务、批次回执、checkpoint、持久 operation 与 READY 状态机 | 既有 provider/CAS/SQLite 实验逻辑、官方 checkpoint、OpenShell stop/observe/start；补可信控制器协调   | A2/A3；在最终入口每阶段强杀，旧代拒写、新代不提前放行、未知结果可对账 |
| 3 项目纵向执行链     | 真实项目导入、共享卷、真实任务与子 Agent，故障后继续                | 固定插件、外部 Volume、官方 AgentLoop；补 staging、冲突策略和引用回收                                | A4/A5；同一版本/transport 的历史、文件、副作用和权限联合核对          |
| 4 调度及可运维发布   | Temporal Run 工作流、worker 池、取消审批、限额、部署升级            | Temporal/现成资源控制；补业务流程、池复用/排空与告警                                                 | A6/A8；证据可复跑、依赖固定、回滚可操作、资源超限被拒                 |
| 5 按服务承诺扩展     | 多控制器、存储/数据库故障、跨执行节点和容量                         | 优先现成数据库/存储/调度能力                                                                         | A7；单节点首版也必须有备份还原；未验 HA 不对外承诺                    |

第一条纵向实现优先完成 A1～A5、A8。调度架构可以同步实现，但 Activity 重试不能越过副作用对账。首版范围允许明确限定为单执行节点；是否支持 PTY/SSH、真实多租户不可信代码、跨节点卷，应作为产品和部署能力开关及验收边界，而非默认开放。

## 验收门槛

实现工作可以立即开始，以下是对应功能投入使用前的门槛；不要求先做完所有研究。第一条纵向链优先完成 A1～A5、A8。若首版只支持单执行节点或禁用 PTY/SSH 等入口，必须在产品与部署配置中明确范围并拒绝未支持调用，不能默认为通过。

| 编号              | 实现验收门槛                                                                 | 必须提供的可核验结果                                                                                                                                          | 关联目标            |
| ----------------- | ---------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------- |
| A1 身份与绑定     | 登录身份到 Workspace/Session/Run/沙盒/Volume 的服务端映射；动态凭据签发/撤销 | 伪造 tenant/Session/卷、旧 capability、直接 SDK/Gateway/管理入口均拒绝；worker 读不到数据库和管理凭据；不撤销共享卷上其他合法 Session                         | EXP-020/025         |
| A2 持久会话       | 完整 provider/checkpoint、持久批次 ID/回执、恢复与审计                       | 旧代 append/flush/close 拒绝；重启/ACK 丢失/事务中途崩溃/调用方崩溃后历史及回执一致；新 worker 自主发现待对账批次                                             | EXP-023～025        |
| A3 接管状态机     | 将服务端入口、撤权、stop/observe/start、CAS、READY 放入同一恢复协议          | 每个阶段强杀控制器及丢回包；旧连接/重连/在跑子进程不能继续写；新代不提前放行；迟到 stop 不杀新实例；UNKNOWN 不盲重放。100ms 入口轮询/断流本身不算进程停止证明 | EXP-019/025         |

## 变更、实验与证据管理

停止开放式扩展研究。只由具体实现缺口、依赖升级或验收失败触发针对性实验；延续既有 EXP 编号，独立新目标才新增编号。未完成项不标为完成或取消。

新运行保存独立 run 目录、scripts、revision/依赖/镜像摘要、操作账本、机器断言、独立观测、失败与清理记录，并生成新清单。历史报告/manifest 不改；不同阶段通过不能拼接成最终链通过。真实模型、外部 HTTP/MCP、所有启用 transport 以最终实现为准。

实验目标及脚本的历史索引见 目标索引（内部归档）；详细协议与既有构建适配见 历史专题（内部归档）。
